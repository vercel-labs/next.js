# Reproduction: next/image fails on AVIF with non-`avif` ftyp major brand (vercel/next.js#84187)

    npm install
    npm run dev   # open http://localhost:3000

## Expected
Both images render.

## Actual
`app/images/mif1.avif` renders broken and the server logs:

```
 ⨯ The requested resource isn't a valid image for /_next/static/media/mif1.<hash>.avif received null
```

`/_next/image?url=%2F_next%2Fstatic%2Fmedia%2Fmif1.<hash>.avif&w=64&q=75` returns HTTP 400.
The second image (identical pixels, ftyp major brand `avif`) returns 200. Also fails with
`npm run build && npm start`.

## Root cause pointer
`detectContentType()` in `packages/next/src/server/image-optimizer.ts` only matches AVIF via the
hardcoded magic `ftyp` + literal `avif` major brand. AVIF files whose major brand is `mif1`
(or `heic`/`msf1`, i.e. any HEIF brand with `avif` only in the *compatible* brands list) fall
through to `detector()`, which reports `'heif'`, and `'heif'` is mapped to `null` -> HTTP 400.
sharp itself decodes the file fine (`metadata().format === 'heif'`).

Regression: in 15.3.4 `imageOptimizer()` did
`detectContentType(buf) || imageUpstream.contentType?.toLowerCase().trim()`, so the upstream/served
`image/avif` content type rescued these files. The fallback no longer exists in current versions.

Both fixture files are generated by `node generate-images.js`.
