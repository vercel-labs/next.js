# not-found.jsx metadata ignored when a catch-all route calls notFound()

Reproduces https://github.com/vercel/next.js/issues/76923

## Run

```bash
npm install
npm run dev
# open http://localhost:3000/abc123
```

## Expected

`<title>Page Not Found</title>` and `<meta name="description" content="The page you are looking for does not exist.">`
(the metadata exported from `app/not-found.jsx`).

## Actual

`<title>Create Next App</title>` and `<meta name="description" content="Generated by create next app">`
(the root layout metadata). The `not-found.jsx` body ("Page not found") *is* rendered.

Deleting `app/[...slug]/` and visiting the same URL renders the expected
`not-found.jsx` metadata, so the bug only occurs when a matched route triggers
`notFound()`.

Verified with `next` 15.1.7, 15.2.1 and 16.3.1-canary.26, with Turbopack and
webpack, in `next dev` and in `next build && next start`.
