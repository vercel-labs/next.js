# Reproduction for vercel/next.js#35345

`useRouter().asPath` renders as `/index` (instead of `/`) in the server-rendered HTML of a
pages-router index page that uses `getStaticProps` + `revalidate`, when the page is
(re)generated by the ISR lambda on Vercel. Only visible via "View Source"; after hydration
the client value is `/`, so DevTools shows the correct value. This breaks `og:url`/canonical tags.

Part 2 of the report (query string missing from `asPath` in the HTML, e.g. `/?zzz=1` -> `/`)
is expected behaviour for statically optimized / SSG pages and reproduces everywhere,
including `next dev` and `next start`.

## Files

`pages/index.js` prints `router.asPath` into the page and into `<meta property="og:asPath">`.

## Reproduce (Part 1 – needs Vercel, next <= 15.x)

```bash
npm install          # next 15.5.23
# deploy this directory to Vercel, then:
curl -s https://<deployment>/ | grep og:asPath
# repeat a few times so the ISR cache goes STALE and the page is regenerated
```

Observed: `<meta property="og:asPath" content="/index"/>` on every ISR-served response.
Expected: `content="/"`.

## Reproduce (Part 2 – locally, any version)

```bash
npm install && npm run build && npm start
curl -s "http://localhost:3000/?zzz=1" | grep og:asPath   # -> content="/"
```

## Version matrix (all deployed to Vercel with the same code)

| next | asPath in ISR HTML |
| --- | --- |
| 12.1.0 | `/index` |
| 13.5.6 | `/index` |
| 14.2.15 | `/index` |
| 15.5.23 | `/index` |
| 16.3.1 | `/` (fixed) |
| 16.3.1-canary.25 | `/` (fixed) |

Self-hosted `next start` / `next dev` never produce `/index` (a request to `/index` 404s).
